# Twinish: your closet, but a game 💅🏻



**Live app:** https://twinish.akroutyosr.workers.dev/ · **API:** https://wardrobe-app-2.onrender.com/api/health

Twinish turns a real wardrobe into a daily styling companion: every item photo-tagged
and embedded, outfits generated from what you actually own, one-tap wear logging that
feeds streaks, challenges and cost-per-wear — plus a shopping-decision agent and a
virtual fitting room.

## Features

- **Daily look** — weather-aware outfit deck generated by Gemini, cached for reuse;
  shuffle, deep-linkable look pages (`/look/{id}`)
- **10-second logging** — 👗 FAB opens a bottom sheet; auto-suggest preselects your
  typical day-of-week outfit; emoji rating saved against a stable outfit id
- **Streaks & challenges** — three challenges auto-generated from your real wear data
  ("finally wear your ankle boots"), advanced automatically on every log, completed
  with a celebration
- **Cost-per-wear everywhere** — set a price during tagging or via a bulk *price sweep*;
  CPW badges on closet cards, wardrobe-average on Home, and a per-wear projection
  inside every shopping verdict
- **Should I buy this?** — a receipt-style verdict from a tool-using agent (tag →
  duplicates → versatility), benchmarked against your real wardrobe average
- **Weekly planner** — assign looks to days; plans persist server-side
- **Virtual fitting room** — sequential IDM-VTON compositing with live step progress
  and before/after

## Engineering notes

- **One deck, four surfaces**: Home/Ideas/Planner/Fitting Room share a single
  weather-bucketed generation context — react-query dedupes to one LLM run per day
- **AI budget guardrails**: `api_usage` meters expensive endpoints against daily caps
  (env-tunable), returning friendly 429s instead of surprise bills
- **Tag cache**: identical photo re-uploads skip the vision model entirely
  (content-hash keyed); buy-checks reuse the agent's own tag result instead of
  re-running vision
- **Truthful UI**: failures never masquerade as success — tagging outages, exhausted
  decks and budget limits each get explicit states
- **Honest streak math**: planner picks live in their own table so *planning* Friday
  never fakes *wearing* anything

## Stack

| Layer | Tech |
|---|---|
| Frontend | TanStack Start (SSR on Cloudflare Workers), React 19, Tailwind v4, TanStack Query/Router |
| Backend | FastAPI on Render, psycopg 3 |
| Database | Supabase Postgres + pgvector (items, wear_log, outfits, challenges, caches) |
| AI | Gemini (tagging / deck generation / shopping agent), all-MiniLM embeddings via pgvector |
| Try-on | IDM-VTON on Hugging Face Spaces (sequential per-garment compositing) |

## Quickstart

### Backend

```bash
cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # then fill in GEMINI_API_KEY + DATABASE_URL
```

- Free Gemini key: <https://aistudio.google.com/apikey>
- Create a free Supabase project with pgvector (`CREATE EXTENSION IF NOT EXISTS vector;`)
  and put the connection string in `DATABASE_URL`
- First-time data copy: `python -m app.scripts.migrate_to_postgres`

```bash
uvicorn app.main:app --reload --port 8000   # docs at /docs
python -m pytest tests -q                   # credential-free smoke tests
```

### Frontend

```bash
cd frontend
npm install          # bun works too; bun.lock is the source of truth
npm run dev          # VITE_API_URL defaults to http://localhost:8000
```

## API overview

Authoritative list lives in `backend/app/main.py`. Highlights:

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/stats` | totals, streak, versatility, avg cost-per-wear |
| GET | `/api/wear-log/suggest-today` | day-of-week outfit suggestion |
| POST | `/api/wear-log/quick-log` | log worn outfit + rating; advances challenges |
| GET/PUT | `/api/planner/week` · `/api/planner/day` | week view + persisted day picks |
| GET | `/api/challenges` | active challenges (auto-generates when short) |
| PATCH | `/api/items/{id}/price` | price for cost-per-wear |
| GET | `/api/items/{id}/cpw` | per-item cost-per-wear |
| POST | `/api/items/upload` | vision tagging (cached, metered) |
| POST | `/api/outfits/generate` | RAG outfit generation (cached, metered) |
| POST | `/api/outfits/{id}/rate` | rate a generated outfit |
| POST | `/api/should-i-buy` | shopping agent verdict (metered, CPW-aware) |
| POST | `/api/fitting-room/tryon` | start sequential try-on; poll session |
